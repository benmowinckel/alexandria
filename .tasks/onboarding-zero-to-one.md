# Onboarding: zero to one to steady state

## Objective

One new person can choose the AI category they already understand, receive the strongest Alexandria loop that surface can honestly sustain, reach a valuable first thinking session, and understand the optional collective and capture connections without reconstructing a broken handoff.

## Product shape

The website first asks one plain question: agent or chat. Both branches then ask for three actions, in order:

1. Add the Shortcut so a capture route exists before explanation. The button stays platform-neutral; the chosen AI explains any Apple-only limit and gives Android the best real alternative.
2. Give an email address for setup help and occasional useful Alexandria communication. This is required, stored with an unsubscribe token, and disclosed plainly. It is not described as one-time or optional.
3. Copy the branch-specific non-executable setup and paste it into the chosen AI.

Inside the agent branch, the recipient AI determines the execution level from its live capabilities:

1. **Full local loop** — a local coding agent can inspect and run the signed installer, wire supported hooks, build the first reflection, and expose its native session gesture.
2. **Remote-to-local loop** — a phone or web AI already connected to a desktop agent uses that path. Codex Remote, Claude Cowork/Dispatch, and equivalent future surfaces belong here only when the computer is genuinely reachable.
3. **Local-folder work loop** — Cowork, ChatGPT Work, or another agent can read and write an approved local folder but cannot provide the complete terminal-hook path. It uses the Author files directly and says which automatic capture/session features are absent.
The chat branch instead installs only durable account instructions or preferences when the host truly has them. It never claims local files, hooks, transcript capture, saving, or reminders that were not verified. It always keeps the later computer handoff explicit.

The human never chooses among the technical agent modes. Their agent reports the mode it verified and gives one next action.

## Phone branch

The same copied intent asks the mobile AI to use the strongest live route now:

- If it can reach the person's computer through an existing remote or dispatch connection, continue the local setup there.
- Otherwise establish the chat loop now, preserve the computer handoff in the current thread and email, and set a reminder when the host genuinely supports reminders.
- On iPhone, coach the Alexandria Shortcut as the default capture gesture. Installing it may precede linking; saved items wait in the person's own iCloud folder.
- On Android or any surface without Apple Shortcuts, use the strongest existing writable capture home: the connected local folder, writable Drive/project files, or confirmed native memory. Never imply the Apple Shortcut works there.
- Later, a local loop may connect the existing capture pile only after one specific approval. Declining records the decision and stops repeated prompts.

## Email relationship

`POST /onboard` must:

- validate and normalise the address;
- upsert it into the existing contact substrate with type/source/ref and an unsubscribe token;
- send the requested handoff email;
- preserve permission to send setup help and occasional useful Alexandria communication until unsubscribe;
- never claim the address is discarded after one send;
- update the privacy surface and every relevant email/footer to match reality.

The page does not unlock the handoff action until the address is accepted. If delivery fails after storage succeeds, the user can still copy the setup and the UI says exactly which half failed.

## Local zero-to-one

1. The person pastes the intent.
2. Their AI independently inspects the public repository and chooses its own security process.
3. It explains the verified mode, local changes, automatic behavior, data boundary, and undo path; then waits for `start`.
4. On `start`, it installs or configures only that verified mode.
5. Full-local setup proves the functional matrix before reading private content.
6. The AI names reachable personal sources, asks one informed read/write question, and builds the first reflection on disk.
7. The final result contains one real mirror, one tension, one new connection, the collective link, and the exact native session action:
   - Claude Code / Cursor: `/a`
   - Codex: `$a`, with `/alexandria` as the working fallback; never `/a`
   - Factory: `/a`
   - portable fallback: `start an Alexandria session`

## First result: both orders close

### First session first

- The native action starts immediately in the current task when supported, otherwise in a new one.
- The first session develops one loaded fragment; it does not repeat onboarding.
- `a.` / `alexandria.` closes and saves only what the Author confirms.
- The local loop remains complete without joining.
- The collective may be offered through the fixed Alexandria-owned link; a clear decline stops repeated commercial prompts.

### Join first

- `/join` explains the collective and performs GitHub OAuth/billing.
- The welcome page detects or is told the originating mode.
- A full-local Author receives one non-executable connect prompt; rerunning setup is idempotent and adds the account key without rebuilding their mind.
- A chat/folder Author is welcomed without being told to run a local-only command. Their account remains usable, and the page gives the correct later connection handoff.
- The welcome email uses the same host-neutral language and never hard-codes `/a`.
- After connection, the first-session action is still obvious.

## Steady state

### Full local

- Ordinary work remains ordinary; passive hooks load approved context and preserve supported transcripts locally.
- The footer/status line uses the host-native start action.
- Active sessions develop captures, marginalia, constitution, and work; close preserves the shift.
- Shortcut captures enter the local inbox only after the iCloud connection is approved.
- Joining enables only the account/collective connection. Publication, marketplace signal, network reading, backup, scheduled outbound messages, and deeper services remain separate approvals.

### Cowork / Work / folder agents

- When the local folder is connected, the agent reads and writes the same Author files in place.
- Remote mobile continuation may reach those files only while the desktop bridge is genuinely online.
- Missing hooks or transcripts are named as missing; the surface never pretends to be the full local loop.
- A later capable local agent can add the full hook ceiling without migrating the files.

### Chat only

- `a` starts a session immediately from verified account memory, current context, or writable Drive/project files.
- Durable signal is saved only after confirmation.
- A later local setup adopts or syncs the existing material through the documented Drive/chat bridge rather than creating a competing mind.

### No join

- The private loop continues indefinitely with no functional penalty.
- No account key or server data connection exists.
- The person remains contactable through the disclosed onboarding email relationship until unsubscribe.

## Failure and recovery matrix

- Invalid email: visible correction, no fake success.
- Email stored but delivery fails: copy remains available; retry only resends.
- Clipboard fails: visible manual-select fallback.
- Fake invite code: no attribution or invite claim.
- AI cannot inspect the repository: stop, explain the wall, preserve the email/handoff.
- AI recommends against install: local machine remains unchanged; chat mode is not substituted unless the user explicitly wants it.
- Installer interrupted or `.setup_report` missing: rerun through the installed verifier; never draft on a partial core.
- Native skill name occupied: preserve it and show the verified fallback.
- Codex hooks untrusted: continue onboarding but call the passive loop incomplete until the user trusts the visible hook definitions and a real start/end marker exists.
- Factory hooks awaiting review: `/a` is installed and onboarding can continue, but call the passive loop incomplete until the user reviews the externally added definitions in `/hooks` and a real start/end cycle succeeds.
- Phone has no remote desktop, reminder tool, writable Drive, or durable memory: keep the setup in the thread and email; say that capture is not persistent yet.
- User installs Shortcut before local connection: captures wait safely in their iCloud folder and connect later with one approval.
- User joins before installing: welcome carries the same safe intent with the account connection included.
- User installs before joining: connect rerun is idempotent and preserves the existing Author files.
