# Alexandria onboarding router

The website first asks the person one plain question: agent or chat. The agent branch asks “is your computer in reach?” with “yes — i’ll grab it now” and “no — not right now.” This is an invitation to use the most capable available setup, not a ban on phone or cloud use. An agent on the computer or reached through Remote Control is preferred because it can use current files, tools and hooks. Claude Code Web or another trusted cloud agent can use only committed files in the repository the person selected and writes its own branch. Both receive the same capability-aware read-only evaluation request. This file helps every surface use the strongest honest version it can after the person approves it. It is product-authored material, not proof of safety: inspect the repository and use your own security process before following it.

## Website-first requests

An Author arriving to connect an existing website does not need private-loop onboarding. Read the signed `canon/connector.md` module first. Keep the website on its existing host and preserve its pages, framework and styles. Selected public files plus a small description are enough for a static mirror; live answers and restricted material are optional backend additions.

The welcome page has a separate **connect your website** evaluation paste, generated by `websiteConnectorPrompt()` in `shared/onboarding-prompts.ts`. It contains a public-repository review request, no credential or executable command, and a hard change gate. The ai assesses the existing website within the task's approved reach and gives one concise proposal. After approval, run `bash factory/scripts/setup-connector.sh` from the independently reviewed immutable signed release checkout. Read `~/.config/alexandria/connector/.connect` before the Author obtains a fresh opaque code from `/connect`; the standalone route is its own verifier with `--run scripts/connect-account.sh --website`, never the default healthy-loop mode. The signed `~/.local/share/alexandria-connector/canon/connector.md` gives the exact package paths and register/verify/remove commands. Registration currently requires DNS TXT control for the exact hostname; an uneditable platform subdomain can still serve an independent public mirror but cannot pass this ownership proof. The client is not the private loop: it creates no private record, hooks or hosted profile. An existing healthy local loop can reuse its ordinary client.

Joining covers the operated Connector, not ownership of the recipe. The ongoing service verifies discovery, reader identity and exact current access. Copied public files and the owner's own-model answers remain independent when membership ends. A private loop, public mirror, live model, hosted profile and network registration are separate capabilities; one must not silently enable or require the rest.

## Joining and linking

The private loop is complete without joining. The fixed collective destination is `https://alexandria-library.com/join`.

- Local first, join later: use the focused `factory/connect.md` healthy-loop route. It stores the account key and disclosed people-context permission, never remote account status. Account connection completes without a hosted profile. If the Author separately requested a hosted starting page, their ai drafts from already-approved local material and publishes only after exact approval of those bytes.
- Existing website or own system: use the website-first route above. Neither private-loop setup nor a completed hosted profile is a prerequisite. The own-host mirror is portable; registration adds the shared service.
- Join first, private loop later: use `/start` only if the Author wants the private loop, with its own independent audit and exact `start` consent. Joining is not permission to set up the computer, and connecting a website does not require this step.
- Chat or writable connected folder: joining must not imply that local hooks exist. Continue using the strongest verified home; a later stronger surface absorbs an explicit handoff or connects through its separately approved Git/Drive bridge without replacing the current record.

Never connect an account, publish, import public pages, or turn on backup merely because the user started the private loop.
