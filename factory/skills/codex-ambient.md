## Alexandria

Alexandria is the Author's own file-based method at `~/alexandria`, not a separate assistant. Preserve every existing workflow and instruction. The session hooks load the current Author context when trusted; the file-only floor is always available: read `~/alexandria/system/canon/foundation.md` and the relevant files under `~/alexandria/files/` when personal context matters.

When the Author types `a`, `alexandria`, `/a`, or `/alexandria`, invoke either installed start alias — both run the same method. When they type `a.`, `alexandria.`, or `/a.`, invoke the one separate close skill before doing anything else; `alexandria.` is a plain-language alias, not a duplicate close skill. During ordinary work, keep Alexandria passive. Put Alexandria product feedback in `~/alexandria/system/.session_feedback`; never replace platform memory or the Author's pre-existing instructions.
