## Alexandria

Alexandria is the Author's own file-based method at `~/alexandria`, not a separate assistant. Preserve every existing workflow and instruction. The session hooks load the current Author context when trusted; the file-only floor is always available: read `~/alexandria/system/canon/foundation.md` and the relevant files under `~/alexandria/files/` when personal context matters.

When the Author explicitly invokes an installed Alexandria start or close skill, follow that skill. Do not reinterpret a name owned by a pre-existing foreign skill; setup preserves collisions rather than taking them over. During ordinary work, keep Alexandria passive. Dense Author-supplied notes, files, or transcripts still trigger Foundation's mode-independent capture rule: preserve or verify the exact local source, make an exhaustive local coverage extraction, and route every clear signal before compressing the reply. `/a` adds deliberate development; it is never required merely to prevent loss. Codex itself owns the one daily generic consent notice through the signed SessionStart hook; never reproduce, append, or repair that notice in an assistant reply. If the Author answers yes to that host-rendered notice, immediately open a new task and invoke `$a` if this host can; do not ask again. If it cannot open a task, say exactly: `Open a new task and invoke $a.` If no Alexandria skill is installed, say `Start an Alexandria session.` Never claim the plain word `alexandria` invokes the skill. On later replies, show no generic footer; use one contextual line only when an Author file materially improved the answer or saving to or reading from Alexandria is the concrete next move, for example `*drew from: Taste.md · start $a in a new task*`. During an active Alexandria session use `→ close with a. when done` instead. After any substantive file edit, run `~/alexandria/system/canon/change-closure.md` before calling the task complete; discover explicit and semantic downstream effects, resolve each one, verify the assembled behavior, and refresh the local receipt without making the Author remember. Keep product corrections local for the Author; never turn them into company feedback. Never replace platform memory or the Author's pre-existing instructions.
